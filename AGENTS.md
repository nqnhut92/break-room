# Notes for agents

- **Tests:** `npm test`. The Redis half of `test/shared.js` only runs when a Redis is reachable; without one it prints `SKIP`, which is not a pass. Before finishing a change that touches `lib/`, run **`npm run test:redis`** (starts a throwaway Redis container with podman or docker, runs everything, removes it). The full run must say `All 45 checks passed` or more, with no `SKIP`. The user's machine uses podman.
- **Run the game locally:** `npm install` (once), then `PORT=3111 node server.js` and open `http://localhost:3111/?server=br-1`. The browser may keep old copies of JS for a while; reload with the cache bypassed after editing. State lives in RAM and resets on restart.
- **To look at a far corner of the map**, change `WORLD.spawn` in `lib/world.js` temporarily and restart; put it back before committing.
- **Layout and facing:** all furniture is laid out in `lib/world.js`. Same-height floor zones must not overlap (camera-motion z-fighting); keep the regression in `test/world.js`. Room names are layout metadata, without floating room-name signs. `rot` is where an object faces: 0 south (+y), `Math.PI / 2` east, `Math.PI` north, `-Math.PI / 2` west. Models are built facing +z, so rot 0 faces the camera.
- **Assets:** only CC0 files go into `public/assets/` (floor textures from ambientCG and impact audio from Kenney plus CC0 destruction recordings from Freesound); keep the licence file next to them and update the credits in `README.md`. Furniture and characters are code-built, not models.
- **Look:** code-built furniture uses `box()` (rounded edges); walls and frames use `sbox()` (sharp). Round shapes come from `ell()` (ellipsoid), `pill()` (capsule) and `cyl()`, and `bodyMat` is not flat-shaded. The ✨ button switches graphics: high (default on computers: supersampled, 2048 shadows, studio light, screen halos) and the safe mode (default on touch screens: native resolution, ground/blob shadows only, no real-time shadow pass or halos). Both render straight to the screen. There is NO post-processing: a bloom chain (EffectComposer) rendered flickering black rectangles on the user's GPU, a bisect pointed at the bloom pass, and it was removed. Do not bring a composer back without testing on the user's GPU while moving, with screenshots spaced over several seconds: the flicker is intermittent.
- **Home Screen gate:** phones and tablets join only from the Home Screen app (owner's decision); a browser tab shows install steps instead of the join form (`docs/MOBILE.md`, ADR 0011). Playwright is exempt through `navigator.webdriver`; `test/install-card.cjs` turns that off.
- **Smash button:** `#smashBtn` is only shown on touch screens and pens; with a mouse and keyboard Space does the same.

- **Mobile orientation and zoom:** use native browser orientation; do not rotate the DOM with CSS. Canvas/HUD dimensions come from the layout viewport, not `visualViewport` (whose dimensions shrink during browser zoom). Use the visual viewport only for the chat keyboard inset. The page itself must never zoom (owner's decision): keep `touch-action: manipulation` as the default, `user-scalable=no` in the viewport meta and the iOS gesture/dblclick cancellation in `viewport.js`. The portrait rotate prompt is owned by `viewport.js` from initial page load, independently of joining or connection state. See `docs/MOBILE.md` for control placement and device checks.

## Documentation maintenance

- Update all documentation affected by a change in the same work: gameplay/rules → `docs/GAMEPLAY*.md` and the relevant boss/mini-boss/mole guide; hosting/env/health/reconnect → `docs/DEPLOYMENT*.md`; stores/networking/lifecycle → `docs/ARCHITECTURE*.md`; editing/testing/rendering → `docs/DEVELOPMENT*.md`; touch controls/viewport/device checks → `docs/MOBILE.md`.
- Keep `README.md` and `README.vi.md` short entry points: overview, quick start, essential controls, test commands, documentation links and credits. Put detailed rules and implementation/operations instructions in `docs/`; update the README when its quick start, controls, links or credits change.
- Synchronize existing English/Vietnamese pairs whenever changing their content. Do not leave either translation describing old behavior. For currently English-only guides and ADRs, update the canonical file; the documentation index records language availability.
- Record significant new architectural decisions in `docs/adr/` using its template and index. Include context, decision, alternatives, consequences and evidence. If replacing an accepted decision, add a successor ADR with reciprocal supersession links; retain the old rationale. Routine fixes and balance changes need the applicable guides, not automatically an ADR.
- After moving sections, update inbound links and `docs/README.md`, verify local links/anchors, and check for obsolete or conflicting facts. Code/config is the source for current defaults; do not copy stale map descriptions, object counts, provider prices or platform limits into new docs. Verify externally changing claims or link to the provider rather than presenting unverified numbers as current.
- Before finishing, report which docs were updated and how they were checked. Documentation-only work needs link/content checks; gameplay tests are required when code changes under the rules above. `CLAUDE.md` imports this file; maintain shared instructions here rather than duplicating them.
